Numbers: inexact and complex

(scheme inexact) has the functions of floating-point maths:

(sqrt 16)                                   ;; => 4
(sqrt 2.25)                                 ;; => 1.5
(exp 0)                                     ;; => 1.0
(/ (round (* 1000 (sin 1))) 1000)           ;; => 0.841
(log 100 10)                                ;; => 2.0
(nan? (/ 0.0 0.0))                          ;; => #t

sqrt of an exact square stays exact; the others return inexact numbers. Complex numbers are written 3+4i, or made from parts; (scheme complex) takes them apart:

(define z (make-rectangular 3 4))
z                                           ;; => 3+4i
(list (real-part z) (imag-part z) (magnitude z)) ;; => (3 4 5.0)
(* +i +i)                                   ;; => -1
(sqrt -4)                                   ;; => 0.0+2.0i
(/ (round (* 1000 (angle 1+i))) 1000)       ;; => 0.785

The magnitude of 3+4i is the length of the arrow from 0 to (3, 4); the angle of 1+i is 45 degrees, π/4. (scm math) adds the constants and a few helpers:

(list PI E)                                 ;; => (3.141592653589793 2.718281828459045)
(factorial 20)                              ;; => 2432902008176640000
(factorial 25)                              ;; => 15511210043330985984000000
(map sign '(-5 0 2.5))                      ;; => (-1 0 1)

Integers have no size limit, so factorial does not overflow.

Accessors: (scheme cxr)

cadr and the other two-letter combinations are in (scheme base); the three- and four-letter ones are in (scheme cxr). Read the letters from right to left: caddr is the car of the cdr of the cdr, the third element:

(define order '("ada" ("Sencha" 2) ("Assam" 1)))
(caddr order)                               ;; => ("Assam" 1)
(caadr order)                               ;; => "Sencha"
(cadadr order)                              ;; => 2

Past two letters, names often read better: (list-ref order 2), or a record.

Code as data: eval

eval runs a datum as code, in an environment that says which bindings it may use. environment makes one from library names:

(eval '(+ 1 2) (environment '(scheme base))) ;; => 3
(eval '(string-upcase "tea") (environment '(scheme base) '(scheme char))) ;; => "TEA"
(eval '(string-upcase "tea") (environment '(scheme base))) ;; => error

The last fails because string-upcase is not in (scheme base). An environment is also a fence: an expression from outside, a formula in a spreadsheet or a pricing rule in a configuration file, can only use what it is given. A calculator that allows arithmetic and nothing else:

(define allowed '(+ - * / min max round))

(define (safe-expression? x)
  (cond ((number? x) #t)
        ((pair? x) (and (memq (car x) allowed) (list? x) (every-safe? (cdr x))))
        (else #f)))
(define (every-safe? xs) (or (null? xs) (and (safe-expression? (car xs)) (every-safe? (cdr xs)))))

(define (calculate text)
  (let ((x (read (open-input-string text))))
    (if (safe-expression? x)
        (eval x (environment '(scheme base)))
        (error "not allowed" text))))

(calculate "(* 2 (+ 3 4))")                 ;; => 14
(calculate "(round (/ 7 2))")               ;; => 4
(calculate "(delete-file \"orders.csv\")")  ;; => error

The check before eval is what makes it safe: even (scheme base) holds procedures that should not run on untrusted input. Prefer data over code where possible; eval is for the cases where users really write expressions.

Reading data: read

read parses one datum from a port: the same syntax as code, but nothing runs. It is the simplest way to store Scheme data in files:

(define p (open-input-string "(tea \"Sencha\" (kg 2)) 42 #(1 2) done"))
(list (read p) (read p) (read p) (read p))  ;; => ((tea "Sencha" (kg 2)) 42 #(1 2) done)
(eof-object? (read p))                      ;; => #t

A configuration file as a list of settings, read with read, is safe in a way that loading it as code is not:

(define dir (mktempdir '(prefix . "r7rs")))
(define config-file (join-path dir "shop.conf"))
(call-with-output-file config-file
  (lambda (out) (write-string "((port 8080) (shops \"Zurich\" \"Bern\") (vat 0.081))\n" out)))

(define config (call-with-input-file config-file read))
(cadr (assq 'port config))                  ;; => 8080
(cdr (assq 'shops config))                  ;; => ("Zurich" "Bern")

Loading code: load

load reads a file and evaluates its forms, as if they were written at that point of the program. Without an environment it uses the program's own top level, which (interaction-environment) from (scheme repl) also names:

(call-with-output-file (join-path dir "pricing.scm")
  (lambda (out) (write '(define (with-vat chf) (* chf 1.081)) out)))

(load (join-path dir "pricing.scm"))
(eval '(with-vat 100) (interaction-environment)) ;; => 108.1
(rm dir 'recursive)

load suits plug-ins and scripts that extend a program. For code of your own, libraries (define-library and import) are better: they are checked when the program starts and say what they export (libraries and programs).

Time: (scheme time)

(real? (current-second))                    ;; => #t
(exact-integer? (current-jiffy))            ;; => #t

(define (time-it thunk)                     ; seconds a thunk takes
  (let ((start (current-jiffy)))
    (thunk)
    (/ (- (current-jiffy) start) (jiffies-per-second))))
(>= (time-it (lambda () (let loop ((i 0)) (when (< i 10000) (loop (+ i 1)))))) 0) ;; => #t

current-second is the wall-clock time in seconds since 1970, with a fraction; current-jiffy counts ticks of an unspecified clock that never jumps, the right one for measuring durations. Dates, time zones and formatting are in dates and times.

R5RS code

(scheme r5rs) exports everything of the previous standard, including null-environment and scheme-report-environment, so old programs run with one import:

(import (scheme r5rs))
(display (eval '(* 4 4) (scheme-report-environment 5)))
